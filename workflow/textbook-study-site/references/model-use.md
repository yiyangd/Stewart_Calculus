# 模型与任务分工

Skill 保存方法、模板、数据合同和检查步骤。它能减少重复解释与重复编码；内容理解、解题和辨别原文错误仍依赖执行模型的能力与实际核验。

不在技能中固定某个模型版本，也不擅自改变用户选择的模型或思考档。以下是本工作流的起始建议，不是质量保证或模型跑分结论：

| 工作 | 起始设置 |
| --- | --- |
| 已核内容的排版、标题、首页链接、静态构建与上传 | 轻量模型或较低思考档；充分利用打包工具。 |
| 读教材、整理知识点、普通例题与逐步解析、双语一致性 | 能处理长文和数学的通用模型，中等思考档；先在一节上评估。 |
| 复杂证明、特殊参数、多解集、教材疑似错误、关键独立复核 | 更强模型或提高思考档，仍进行精确计算与原文核对。 |

降低用量的可靠做法是按章节和题段制作、保留已核 JSON、复用模板，并把复审集中在关键问题。不要用缩短步骤、省略小问或减少核验来节约用量。

用同一章比较设置：原题转录是否准确、题目与子问有无遗漏、复杂根或端点是否正确、修改后能否通过同一验收。通过后再批量扩展；发现漏项时先检查范围、来源和工具是否齐全，再决定是否提高档位。

官方说明（本次整理时查询于 2026-10-14；模型和可用档位可能变化，下次回答具体型号时重新查）：

- [Model selection](https://developers.openai.com/api/docs/guides/model-selection)：选择模型与思考档，并在同样输入下比较满足质量标准的最轻设置。
- [Managing usage in Work and Codex](https://help.openai.com/en/articles/20001516-managing-usage-with-gpt-6-astra-in-work-and-codex)：模型与思考档分开选择；更高思考档可能增加用量，不保证更好结果。
